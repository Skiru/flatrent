# Flatren Project Risk Register

This document tracks identified architectural, implementation, and operational risks, their impact, and their respective mitigation strategies.

| ID | Risk | Category | Probability | Impact | Mitigation Strategy | Status |
|----|------|----------|-------------|--------|---------------------|--------|
| **RSK-01** | Concurrent tenancy activation requests bypass pre-transaction checks, leading to overlapping rentals. | Consistency | Medium | High | Enforce database-level PostgreSQL exclusion constraints on `rental_unit_id` and date range, combined with transaction locking/optimistic concurrency (OCC) on Tenancy states. | Mitigated (ADR-004) |
| **RSK-02** | SQS Standard queue semantics (at-least-once, out-of-order) cause stale data overwrites in Maintenance. | Messaging | High | Medium | Implement an idempotent `inbox` table, track `aggregateVersion` on the consumer, ignore stale messages (`incomingVersion <= currentVersion`), and handle version gaps with an explicit reconciliation protocol. | Mitigated (ADR-005) |
| **RSK-03** | DynamoDB transaction limitations (max 100 items, 4MB payload, unique item target) fail on large batches. | Persistence | Low | Medium | Implement a preflight transaction-budget guard checking total write sizes and action counts before executing transactions. Restrict commands to one aggregate modification. | Mitigated (ADR-005) |
| **RSK-04** | Node.js / pnpm corepack version drift on the host machine prevents consistent execution of verification tools. | Environment | High | High | Fixed Node.js version to `v22.23.1` (LTS) via NVM and pinned pnpm to `11.13.1` in the workspace core. Sourced NVM in all execution environments. | Mitigated (C0-Check) |
| **RSK-05** | Network I/O performed within database transactions blocks database connections, leading to pool exhaustion. | Performance | Medium | High | Strictly forbid remote Module API calls, HTTP fetches, and SQS/SNS publishing inside transactional scopes. All external effects are deferred to an outbox table. | Mitigated (ADR-005) |
| **RSK-06** | Redis cache outages or state drift cause stale authorization decisions or cascade failures. | Reliability | Medium | Medium | Implement Redis strictly as a cache-aside layer. Business operations and authorization decisions degrade gracefully to PostgreSQL/DynamoDB on cache failure. | Mitigated (ADR-006) |
| **RSK-07** | MiniStack RDS/ElastiCache data-plane containers fail to start or allocate ports due to Docker permissions or network exhaustion. | Integration | Medium | High | Mount the host `/var/run/docker.sock` to MiniStack container, discover endpoints dynamically through health APIs, and write a programmatically verified bootstrap and doctor checklist. | Mitigated (ADR-006) |
